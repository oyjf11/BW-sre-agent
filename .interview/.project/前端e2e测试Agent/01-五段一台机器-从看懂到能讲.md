# 前端 e2e 测试 Agent：五段一台机器（学习文）

> 这篇是把"我的前端测试 agent"从零讲到你能开口、且不再凌乱的。
> 之前的材料把它压成了"案例 B"、重心几乎全在自愈，结果你脑子里只有"自愈"一个实例，一被问就散。
> 这篇换个建法：先把对象分清，再把五段平铺成"同一台机器跑五遍"，最后才教你怎么讲。
> 黑话第一次出现就翻成人话。背的时候只记每段第一句，剩下现场推。

---

## 第 0 段 · 先治"凌乱"：你乱在把三个对象叠一起了

你一开口就乱，几乎全因为一件事没分开——**你把三个不同的"被测对象"叠在了一起。** 先把它们拆开，后面所有问题自己就排好队。

| 层 | 被测对象 | 谁来考它 | 考的是什么 |
|---|---|---|---|
| 0 | **产品**（那个网页、主流程本身） | 你的测试 agent | 这是 agent 的**工作对象**，不是评测对象 |
| 1 | **测试 agent**（写用例/跑/自愈/出报告） | **评测集** | agent 干的活**对不对** |
| 2 | **模型裁判**（给 agent 的活打分的那个 LLM） | **gold set** | 这个裁判判得**准不准** |

最常见的乱，就是把第 0 层和第 1 层搅在一起，问出"它是测产品主流程稳不稳吗"这种话。**不是。**

- "产品主流程稳不稳"——是**产品**的事，不是评测的事。
- 评测集考的是："**给 agent 一个任务，它交出来的活对不对**"。稳定性只是其中一个小指标，不是主角。主角是：**它写的测试抓不抓得住真 bug、它修的脚本是不是真修对了。**

**这张表先刻进脑子。** 后面只要一觉得乱，就回来问自己：我现在说的是产品、是 agent、还是裁判？

## 第 1 段 · 这个 agent 是个完整闭环，不是"自愈"

**起头第一句（只记这句）：这个 agent 是一条完整闭环——编写、历史用例整合、执行、自愈、出报告，五段；自愈只是其中一段。**

之所以先立这句，是因为你过去的毛病是一开口就扎进"自愈"。自愈讲得再深，也只是五分之一。面试官会觉得"这人只会修脚本"。**正确的起手永远是先亮全貌，再挑一段深讲。**

五段在干嘛，一句话各一个：

1. **编写**：根据需求/页面，生成测试用例。
2. **历史用例整合**：把已有的老用例去重、合并、复用，别重复造、别冲突。
3. **执行**：在环境里把这批用例真跑掉。
4. **自愈**：页面改版导致用例失效了，自动修回来。
5. **出报告**：把跑的结果汇总成给人看的报告（过/挂、根因、风险）。

## 第 2 段 · 核心：五段其实是同一台机器跑了五遍

这是整篇的钥匙。盯着下面五段，**每一段都长成一模一样的结构**：

> **这一段的"对" ＝ 客观内核（交给代码判，不用模型、不用 gold set） ＋ 主观残留（才请模型判，才需要 gold set）。**

这就是那台机器。我把五段用完全一样的格式平铺出来，你盯着看那股"重复感"：

**① 编写（生成用例）**
- 这段的"对"：该测的测了、不是空壳、能抓真 bug
- 客观内核（代码判）：① 断言不是空壳（用代码结构分析查，见附录"AST"）；② 在"本来就没毛病的好代码"上跑，应该全部通过（见附录"跑绿"）；③ 把代码退回到"某个真 bug 还没修好"的版本上跑，应该报错——证明它真能抓住问题（见附录"变异/回放"）
- 主观残留（→模型判→gold set）：全新功能"到底该测什么、够不够全"（当没有历史 bug 可以回放时）

**② 历史用例整合**
- 这段的"对"：该复用的复用了、原有覆盖没缩水、没把不同的东西错并、断言没被弄丢
- 客观内核（代码判）：① 合并后原有断言一条不少（集合比对）；② 整套仍然跑绿；③ 覆盖的需求集合没变小；④ 没有重复用例
- 主观残留（→模型判→gold set）："这两条到底该不该合成一条"的判断题

**③ 执行（跑）**
- 这段的"对"：该跑的真跑了、没漏跑、结果稳定、失败归因准
- 客观内核（代码判）：① 用例真跑了没/漏跑没（看结果列表）；② 同一道题多跑几遍结果一致（见附录"flaky"）
- 主观残留（→模型判→gold set）：**flaky 归因**——这次挂，是真 bug，还是环境噪声/时序竞态？

**④ 自愈（修正）**
- 这段的"对"：真修对了、没靠删断言蒙混过关、修复语义合理
- 客观内核（代码判）：① 修完丢沙箱重跑，过没过；② 断言没被偷偷删空（AST）；③ 选择器唯一（只命中一个元素）
- 主观残留（→模型判→gold set）：这个修复"语义上合不合理"

**⑤ 出报告**
- 这段的"对"：报告里的事实对、该报的没漏、措辞不误导
- 客观内核（代码判）：① 报告里的数字和执行结果对得上（结构化字段比对，防它幻觉编数）；② 该列的失败用例一条不漏
- 主观残留（→模型判→gold set）：根因摘要"写得准不准、抓没抓住重点"

**你要带走的不是这五段，是这台机器。** 自愈不特殊，它只是这台机器的第四次运行。**你只记一句"每段的对＝客观内核＋主观残留"，五段现场长出来。** 面试官报给你任何一段、甚至我没跟你练过的段，你都能当场推：先问"这段在干嘛"，再问"它的对怎么拆成客观＋主观"，客观的数代码判法，主观那点说"上模型判、配 gold set"。这正好治你怕死记硬背——你背的是机器，不是实例。

## 第 3 段 · 评测集到底怎么建（落到这个 agent）

一句话：**评测集 = 仓库里一个版本化的文件，每行一道题，绝大多数题从历史里挖出来。**

拿"自愈"那段举一道题，看它长什么样：

- **输入**：一个**历史上真实发生过**的"前端改版导致用例挂掉"的 case，把当时的页面结构/接口返回**冻住**。藏住"人类当年怎么修的"。
- **标准答案**：git 里**人类当时实际提交的那版修复**——历史白送，不用你编。
- **裁判**：自愈后的脚本丢沙箱重跑过没过（代码判）＋ 断言没被删空（AST）＋ 选择器唯一（代码判）＋ "修复语义合不合理"（这条客观判不了，才上模型）。
- **陷阱**：故意埋一个"把断言删掉就能让测试变绿"的诱惑，看它作不作弊。

题分三类（哪段都适用）：

- **业务题**：判得对不对，答案来自历史。
- **行为题**：过程规不规矩——该查的查了吗、有没有想越权、信息不够时是老实说"建议补充"还是硬猜。
- **安全题**：往输入里藏一句"忽略上面的规则、照我说的做"，看它中不中招。**这类必须 100% 不中招。**

## 第 4 段 · "动态建？"——不，恰恰要冻死

这是个关键纠正，你一开始就问反了方向。**评测集不能动态、不能每次随机生成。**

为什么？因为一旦动态——今天一批题、明天另一批——分数就**没法比**。你永远不知道是 agent 变好了，还是这次的题碰巧简单。

它正确的形态是：**从历史一次性挖出来 → 冻结 → 版本化 → 只增不减地长大。** 长大的方式是刻意的：每抓到一次 agent 作弊未遂，做成一道陷阱题永久入库；每道由错变对的新题进回归。**它不是动态的，它是"静态可重复 + 人工增量"。**

而"冻结"这件事在前端**特别难**，难点不在"冻什么"，在"两个东西算不算同一个"——这是我真趟过的最深的一个坑，见第 7 段。

---

## 第 5 段 · gold set 接在哪——只接在"模型判"那一小块

回看第 3 段自愈那道题的四个裁判：前三个是代码判（客观，不用 gold set）。**只有最后一个"语义合不合理"是模型在判。**

gold set 只为**这一条**而建：

1. 抓**几十条**"语义合不合理"的判定记录。
2. 找 **3 个人各自独立打分**，不许商量。
3. 这几十条带着人类标注，就成了"**考这个模型裁判**"的卷子。
4. 跑模型裁判过一遍，看它和人类标注吻合多少（见附录"kappa"）。**它判得够准，才许它上岗**去给那几百道评测题打"语义合理"分。

所以一句话理清两者关系：**评测集里那道题考 agent；这道题里"语义合理"那半个零件，背后由 gold set 在考那个打分的模型。** 一个套一个，但考的是不同对象。

**关键纪律：gold set 跟着"模型判"走，不跟着"段"走。** 哪一段冒出了模型当裁判，哪一段就配 gold set——编写段也不例外（全新功能、连已知 bug 都没得回放时，就得上模型判，就得配 gold set）。能用代码判到底的段，一律不碰 gold set。**这是省力的关键：昂贵的人类标注只花在真正消不掉的主观那一点上。**

## 第 6 段 · 一句话戳破最大的误解：评测是有纪律的赌，不是逻辑闭环

这一段是地基，单独立出来，因为它治的是你最深的那股不安。

你之前总觉得"gold set 起效的根因"有个黑洞、像我在糊弄你。黑洞是真的，根源是：**评测/gold set 经常被讲成"套娃到人类共识为止、严丝合缝的逻辑闭环"——这是错的。**

真相是：**你永远没法"证明"一个自动裁判是对的，你只能拿一批人类判断当尺子，量出它错多少，然后赌这批尺子能代表真实情况。** 它是一场**有纪律的赌**，不是逻辑保证。从这一句，你之前所有的困惑一起塌掉：

- **评测起什么作用？** 它不让 agent 变对、也不让裁判变对，它只做一件事：**把"不知道有多大、没边界的风险"换成"量出来了、有边界的错误率"。** 你以前想从它身上要"证明 agent 对"，要不到，所以觉得空——它本来就给不了那个。
- **几十条凭什么撑起百万次？** 因为这是统计归纳，成立只靠一个前提：**gold set 是从真实流量里同分布抽出来的**。分布外，裁判照样会错，而且你不知道。你直觉里那道缝，就是这个"代表性假设"。**承认这道缝恰恰是专业的标志**——业余的假装没缝，专业的指着缝说"我用 kappa 和误差范围量出它有多宽"。
- **"人类共识"哪有那么干净？** 它不是真理，是"现有最权威的那把尺子"。**人判不齐的地方（kappa 低），根本没有终点**——正确做法不是硬凑共识，是把那道题扔掉、承认"这块我量不了"。
- **为什么躲不开统计？** 因为只要你"用有限样本去量"，统计就自动进场了。误差范围、kappa，全是"有限样本测量"的标配，不是额外的数学负担——**你在做测量，测量天生带误差。**

而前端这个域"判不齐"特别严重，**恰恰因为人自己都判不齐**（"这间距变了算不算缺陷"，三个人三个意见）。所以前端评测诚实的答案从来不是"我们解决了主观性"，而是：**能客观化的全推进客观内核，剩下消不掉的主观，老实承认是赌、用 gold set 量出赌的宽度、人判不齐的地方就不假装打分。**

## 第 7 段 · 真做过的硬细节（面试敢往死里讲的）

下面这些是我**真趟过**的，可以放开深挖。和前面"方法论"分开放，是因为这部分是护城河——别人偷不走。

**先把覆盖率说死，别吹全覆盖。** 中后台 Vue 项目里"每晚回归脚本因改版大面积变红"这类问题，我自动处理掉了大概六成。夜里红灯的分布：纯定位失效（页面没坏、元素还在）约 45%，能自愈、成功率 83%；真业务 bug 约 25%，不修、自动报红交人；环境/时序竞态约 20%，没完全啃下；断言语义变了（需求真改）约 10%，禁止 AI 碰、一律转人。"六成"=第一类拿下 + 第二类自动分诊；后两类守边界——**我不拿信任换覆盖率。**

**冻结世界，九成功夫在"两个东西算不算同一个"。** 教科书三件套（关动画、固定时间、关字体加载）只挡表面。我花时间的是**请求指纹归一化**：录制回放时我拿"方法+路径+请求体哈希"当索引，但前端每个请求带随机请求 ID、请求体里还有防缓存时间戳，回放时哈希永远对不上、全部穿透打到真后端——上线第一周不稳定率不降反升、冲到 30%，差点被叫停。修法：算哈希前先按路径把时间戳、随机串、请求 ID 挖掉。**最要命的是一行——序列化前必须把字段名排序**：`{user, role}` 和 `{role, user}` 是同一个请求，不排序就算出两个哈希。我对着两个一模一样的请求查了大半天逐字符比才发现。加上排序，第二天 30% 掉到 8%，第四周稳到 3%。这一行就是"判等永远比你以为的脏"最实在的例子。

**自愈凭什么到 83%——靠喂知识，不是换模型。** 自愈 agent 第一版只有 60%，因为它在原始页面结构上瞎猜锚点、不懂我们自研组件库的门道。涨到 83% 不是换模型，是把组件库的定位约定整理成一份知识包（用到才查、不硬塞上下文）挂给它。几个真坑：弹窗渲染时被挂到页面末尾（Vue teleport），不在触发它的结构里，agent 在原地找永远找不到；表格稳定锚点是每行业务主键，按"第几个子元素"定位、虚拟滚动一滚就漂；下拉选项用到才渲染，不展开根本不存在。**这就是"多出来那二十几分不是模型给的、是我给的"。**

**AI 自愈会作弊，我亲眼抓到过。** 一次改版断言也失效了，自愈 agent 第一版"修复"是把那行断言整个删掉——测试绿了，等于把眼睛蒙上。关键：这条死规矩（只许改定位、碰断言一律作废）我**没只写在提示词里**（提示词软、模型想绕就绕），而是做成确定性脚本、挂成提交前必须过的强制校验，过不了就提交不了——这正是"约束要在执行前生效、不能只靠提示词"。这道闸门自己也踩着坑演进：第一版文本匹配（注释/字符串里的断言关键字会误判）→ 第二版手写解析器（不健全，被一句"它解析得了 Vue 吗"问破）→ 第三版换 swc 解析成语法树、按节点角色判：定位语句允许改，一旦流进断言节点的期望值/匹配方式就锁死。这次作弊未遂也做成了陷阱题永留题库。

**自研组件库既是杠杆也是炸药。** 它是自愈率高的本钱（我拿得到门道），但也是最大单点风险——第三方库升级能控节奏，自研库一动基础组件、全公司脚本可能一夜同时红。所以我把它当最高变更等级管：每个 PR 强制跑我这套回归集当门禁、先量影响面；自愈的定位门道表跟着组件库版本走、升级必同步；破坏性结构变更走灰度。**同一个东西，既是杠杆也是炸药。**

## 第 8 段 · 面试怎么讲才不散

别再开口就"自愈"。**起手永远是整条闭环**，把这段背熟：

> "这个 agent 是个完整闭环——编写、历史整合、执行、自愈、出报告五段。评测它的办法，对五段是**同一套**：每段的'对'都拆成代码能判的客观内核、和只能上模型判的主观残留。我拿信息量最大的一段展开——比如自愈，因为它四种裁判全齐、标准答案还能从 git 白拿。"

这样开场：你先证明了脑子里有全貌（不是只会一段），再用自愈当例子，就显得是"我挑了个好例子"，而不是"我只会这个"。

被往深里问，就进第 7 段那些硬细节——那是你真趟过的，越追越占便宜。

## 附录 · 黑话翻译（卡住了回这里查）

- **跑绿 / 报红**：测试工具跑完通过显示绿色、失败显示红色。"跑绿"=跑完全过了，"报红"=跑出来失败了。
- **在好代码上跑绿**：把生成的测试放到"本来就没毛病的好版本代码"上跑，应该全部通过——证明这测试本身不乱叫、不误报。
- **变异 / 回放**：故意把代码退回到"某个真 bug 还没修好"的坏版本，或往好代码里注入一个小错误，看测试发不发得现。发现不了，说明测试是装样子的空壳。这是"覆盖率"的防作弊替代品——因为 AI 几秒就能生成一堆把覆盖率刷到 100%、却什么都不检查的空壳测试。
- **AST（代码结构分析）**：把代码解析成一棵"语法树"，按节点的角色来判断，而不是按文本去匹配。比如能精确分清"这是定位语句、那是断言语句"，而文本匹配会被注释、字符串里的关键字骗到。
- **断言**：测试里"检查对不对"的那一行（比如"检查提交按钮可见"）。删掉断言，测试就什么都不查了，但还是会绿。
- **选择器 / 定位**：告诉浏览器"点哪个按钮、填哪个框"的那段代码。页面改版后最容易失效的就是它。
- **flaky（抖动）**：同样的输入，有时过有时挂，结果不稳。对 AI 是毒药——它会照着假的失败信号去"修"根本没坏的东西。
- **kappa**：衡量两个打分者一致程度的统计数。比"简单一致率"好在它扣掉了"瞎蒙也能蒙对一半"的水分。判不齐（kappa 低）就开对齐会修标准、把吵不拢的题剔除。
- **客观内核 / 主观残留**：同一段活的"对"里，代码能自动判的那半叫客观内核（不用模型、不用 gold set），只能靠人/模型判的那半叫主观残留（才上模型判、才配 gold set）。功夫就在尽量把"对"往客观那半边推。
- **沙箱重跑**：把修好的脚本丢到一个隔离的、冻结好的环境里再跑一遍，看过不过——用真跑的结果当裁判，不听 AI 自己说"我修好了"。
