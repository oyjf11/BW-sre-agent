企业级 AI Harness 框架面试题 100 道

下面这套题不是某家公司的“泄题”，而是基于 OpenAI、Anthropic、Google、Microsoft 近期公开的 Agent 工程实践、招聘要求和生产级框架设计整理出的大厂面试问题模型。

当前业界对 Harness 的理解已经明显超出 Prompt Engineering：它是包裹在模型外部的一整套执行系统，包括指令、上下文、工具、环境、权限、任务编排、状态持久化、验证、评测、可观测性和反馈闭环。OpenAI 对 Codex Core Agents 岗位的描述也直接强调：Harness 的职责是将模型能力转化为真实世界中的安全行动。

题目也结合了你简历中的企业 AI 辅助研发工具包、Skills/SubAgent、MCP、Playwright 门禁、Bad Case 迭代和多 Agent 协作经历。

标记说明：

- ★：高频核心题，必须能深入回答
- ★★：高级岗位常见系统设计题
- ★★★：架构师、技术负责人或头部 Agent 团队深挖题

1. ★ 什么是 Agent Harness？它与 Agent Framework、Agent Runtime、Workflow Engine 有什么区别？

建议补充的高级追问方向

上面是完整的 100 道主问题。真实的大厂面试通常不会问完，而会选择其中一题连续深挖。例如：

什么是 Harness？
↓
它和 Runtime 有什么区别？
↓
状态存在哪里？
↓
进程挂了怎么恢复？
↓
工具重复执行怎么办？
↓
如何保证幂等？
↓
如何评测恢复机制？
↓
生产 Trace 如何反哺 Eval？

真正的考察重点不是“知道多少名词”，而是能不能形成完整闭环：

任务如何进入
→ 如何理解和规划
→ 如何获得上下文
→ 如何调用工具
→ 如何限制权限
→ 如何持久化状态
→ 如何验证结果
→ 如何处理失败
→ 如何评测效果
→ 如何根据生产数据持续改进

Anthropic 将完整 Eval Harness 定义为能够提供任务指令和工具、并发执行任务、记录全过程、完成评分并聚合结果的基础设施；Google 则同时强调最终结果和 Agent 执行轨迹的评估。换句话说，企业级 Harness 不能只判断“模型最后说得对不对”，还必须判断它是否通过正确、安全、经济的路径完成任务。

从你当前经历看，最容易被重点追问的板块是：

1. Skills、SubAgent 和 MCP 的能力边界
2. AI Coding 工作流为何不是简单 Prompt 集合
3. Playwright 如何成为确定性质量门禁
4. Agent 状态管理、断点续传和任务恢复
5. 工具权限与高风险动作审批
6. Bad Case 如何进入离线评测集
7. 如何证明 50% 效率提升和质量提升
8. 20 Commands、22 Agents、75 Skills 是否存在过度设计
9. 为什么需要多 Agent，而不是一个强模型
10. 你的体系能否独立于 OpenCode，演进成产品化 Harness 平台
